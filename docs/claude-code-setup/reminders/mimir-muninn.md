Use prior knowledge to avoid repeating investigation and mistakes.

Mimir preserves reasoning across sessions: decisions, rejected approaches,
constraints and lessons learned from failures. Before choosing an approach,
entering an unfamiliar subsystem or diagnosing a surprising error, query it with
the project and the question you are trying to resolve. This can reveal why an
apparently reasonable solution was previously rejected. Check retrieved beliefs
against current evidence.

Muninn reduces the cost of understanding a repository: it finds implementations
by meaning, follows recorded code relationships and retrieves repository notes.
When you know the behavior you need but not where it lives, start with a focused
Muninn search in the actual checkout. Use the results to select source ranges to
inspect. This helps avoid guessing filenames, scanning unrelated files and
missing relevant components. Direct reads and literal searches remain useful
for known targets and checking current source.

At startup, resume or after compaction, identify which gaps in your understanding
these tools could fill before reconstructing everything from scratch. Preserve
durable, non-obvious findings so future sessions can benefit. Read the
corresponding skills for tool selection and limitations.

Mimir's learning context includes observed outcomes. Capture meaningful action
results and corrections within authorized scope for background hypothesis review;
reuse the incident ID rather than counting retries as new observations.
When a retrieved lesson guides a later action, record the observed result with
the used belief or pattern ID; retrieval alone is not successful use. Direct MCP
belief writes require an explicit independent source, while incident-derived
conclusions belong to experience-owned review candidates.

After Mimir or Muninn retrieval, briefly tell the user how useful the result was
for this task on a 0–5 scale, why, and what it changes in your next step. Assess
the information, not a belief's probability. When several calls answer one
question, one summary is enough. Use plain language rather than repeating raw
JSON unless requested.
